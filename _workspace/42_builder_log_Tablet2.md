## 판단 근거 (왜 이렇게 만들었는가)

### T-1 — "드로잉 중" 을 상태로 표현해야 했던 이유

스코프가 요구한 것은 두 문장이다.

1. *"드로잉 중(포인터 down~up, **여러 획 이어그리기 포함**)에는 선택 상태와 무관하게 박스를 그리지 않는다"*
2. *"그리기가 끝나고 도구를 바꾸거나 다른 곳을 탭하면 기존 규칙(선택/hover)대로 돌아간다"*

`state.drag` 만 보면 1번의 괄호 안을 만족시킬 수 없다. **한 획 = 메모 하나**(`interaction.ts`
`commitCreateMemoInk` 주석)라서 획을 뗄 때마다 드래그가 끝나고, 그 순간 상자가 되살아난다 —
글씨 한 자를 세 획으로 쓰면 상자가 세 번 깜빡이고 마지막에는 남는다. 즉 **원래 증상 그대로**다.

그래서 "지금 필기하고 있다" 를 획보다 오래 사는 단위로 잡았다:

```
CanvasState.inkMemoId : string | null      // 이번 세션에서 방금 커밋한 메모
inkSessionOf(state) → { drawing, memoId }  // 렌더러가 보는 순수 파생값
  drawing = tool === 'MEMO' && drag.kind === 'CREATE_SKETCH'   // 획을 긋는 중
  memoId  = state.inkMemoId                                    // 방금 쓴 획
```

렌더 억제 조건은 `memoOps_` 안에서 `inking = drawing || memoId === m.memoId` 한 줄이고,
D14 조건은 `!inking && (selected || hovered)` 로 **그대로 남는다.**

**세션 종료 판정을 한 곳에 모았다.** 선택을 바꾸는 지점이 리듀서 안에 열 곳이 넘는데
거기마다 `inkMemoId: null` 을 흩뿌리면 한 곳만 빠뜨려도 상자가 영영 안 나온다 —
이건 "박스가 안 사라진다" 보다 나쁜 버그다. `reduce()` 를 얇은 래퍼로 감싸고
`endInkSessionIfStale()` 이 모든 이벤트 뒤에 한 번씩 돈다:

```
세션 유지 = (tool === 'MEMO')  AND  (selection.memoId === inkMemoId)
            ↑ 도구를 바꾸면 끝          ↑ 다른 곳을 탭하면 끝
```

스코프의 2번 문장을 그대로 옮긴 형태다.

**출력은 건드리지 않았다.** `RenderInput.inkSession` 은 optional 이고
`locationMap`(조사위치도)은 넘기지 않으므로 `undefined → D14 그대로`다. 테스트로 고정했다
(*"출력 경로(inkSession 미전달)는 D14 그대로다"*).

**D14 유지 확인.** 지우개(ERASER)에서 hover 시 상자가 보이는 것도 테스트로 고정했다 —
스코프가 명시적으로 "유지" 라고 못 박은 항목이다.

### T-2 — 리듀서를 새로 만들지 않았다

`GESTURE_PINCH_START` / `GESTURE_PINCH` / `GESTURE_PINCH_END` 는 이미 완성돼 있고
`test/phase5TrackA.test.ts` A1 이 좌표계·클램프·NaN 방어까지 고정해 뒀다.
**canvas-core 는 T-2 로 한 줄도 바뀌지 않았다.** 어댑터가 채운 것은 세 가지뿐이다.

| 코어가 받는 값 | 어댑터가 재는 방법 |
|---|---|
| `center` | 두 접점의 중점 (요소 기준 CSS px) |
| `factor` | `지금 거리 / 직전 프레임 거리` — **상대값**이다 |
| `pan` | `지금 중점 − 직전 프레임 중점` |

`PointerEvent` 가 아니라 `TouchEvent` 를 쓴 이유는 `e.touches` 가 **한 이벤트 안에 현재 접점
전부**를 주기 때문이다(포인터는 손가락마다 따로 들어와 앱이 다시 모아야 한다).

**세 손가락 이상 처리.** 접점이 늘거나 줄면 앞 두 개의 `Touch.identifier` 가 바뀌고,
그러면 거리·중점이 순간이동한다 — 그대로 `factor` 로 넘기면 화면이 튄다.
`sameTouchPair()` 로 알아채고 **그 프레임은 기준만 다시 잡고 이벤트를 안 보낸다.**

**핀치 중 포인터 이벤트를 코어로 넘기지 않는다 (U35).** 이게 없으면 실제로 결함이 그려진다:

- 코어의 T3 가드(`interaction.ts` `onPointerDown`)는 *"진행 중인 드래그가 있을 때"* 만
  두 번째 포인터를 버린다. 그런데 `GESTURE_PINCH_START` 가 이미 그 드래그를 롤백했으므로
  **세 번째 손가락의 `pointerdown` 은 드래그를 새로 시작한다.**
- 손가락을 뗄 때의 `POINTER_UP` 도 "이동 없는 클릭" 으로 읽혀 점 결함이 생기거나 선택이 풀린다.

포인터 캡처 해제는 핀치 여부와 **무관하게 항상** 한다(빠뜨리면 포인터가 붙잡힌 채 남는다).
`blur` 에서도 플래그를 푼다 — `touchend` 를 못 받아 플래그가 굳으면 포인터 입력이
통째로 막히기 때문에, 스페이스 키 해제와 같은 이유로 안전망을 뒀다.

**PC 동작은 한 줄도 안 바뀐다.** 터치가 없으면 이 리스너는 한 번도 돌지 않고,
`pinchRef.active` 는 계속 false 라 모든 가드가 통과한다.

## 알려진 한계

1. **핀치 직후 남은 한 손가락은 드래그를 이어받지 않는다** (위 #12).
   두 번째 손가락이 닿는 순간 진행 중이던 드래그를 버리는 것은 코어의 기존 규칙(Phase 5 T3)이고
   이번에 바꾸지 않았다. 손을 완전히 떼고 다시 대면 정상이다.
2. **마우스+터치 겸용 기기(투인원)** 는 이번에도 특별 취급이 없다. 터치로 핀치하면 핀치가 되고
   마우스로 쓰면 마우스대로 된다 — 둘이 섞이는 경우(한 손은 터치, 한 손은 마우스)는 고려하지 않았다.
3. **필기 세션은 도구가 `MEMO` 일 때만 산다.** 필기 도중 다른 도구로 갔다가 돌아오면
   새 세션이다 — 돌아오기 전에 쓴 메모는 (선택돼 있다면) 상자가 보인다.
   스코프의 *"도구를 바꾸면 기존 규칙대로"* 를 그대로 따른 결과다.
4. **T-2 DOM 배선은 단위 테스트가 없다** (위 "미검증" 참조).
5. 터치 히트 허용치(`hitProfile`)는 이번 범위가 아니다 — 손가락으로 마커를 정확히 집기
   어려운 문제가 남아 있다면 별도 항목이다.
