## Q1 · plan-reviewer · 2026-08-22 · Phase 3

**막힌 지점:**
도면에서 [점] 도구로 위치를 찍는 **그 순간** 결함(Defect) 레코드가 만들어져 저장되는가?
만들어진다면 부재·결함유형이 아직 비어 있는 **미완성 결함**이 존재하게 된다. 이걸 허용하는가?

상세기획 §2.5 **G7** 이 이 항목을 `⬜ 확인 필요` 로 남겨두었는데,
Phase 3에서 "점을 찍는다"를 구현하는 순간 반드시 걸린다.

**왜 임의로 정하면 안 되는가:**
- 좌측 조사항목 리스트에 **찍자마자 1건이 늘어나는지** 여부가 달라진다 (사용자가 즉시 보는 동작)
- 허용하면 `Defect.status` 또는 별도 플래그에 `DRAFT` 개념이 **데이터 모델에 굳는다**
- 불허하면 마커 생성이 "클릭 → 필수 항목 입력 완료 전까지 임시" 라는 완전히 다른 흐름이 된다
- 출력 시 미완성 결함을 어떻게 다룰지(경고·제외)가 Phase 4에 연쇄된다

**선택지:**
- **A. 허용 — 찍는 즉시 저장, 미완성 상태 허용**
  → 리스트에 즉시 뜬다. `미완성 N건` 배지 + 출력 시 경고가 필요하다.
  → 근거: 젠트릭스 실측 화면(`스크린샷 _01`)에서 마커 37번이 이미 도면에 있는데
     우측 패널의 결함유형은 `선택해주세요.` 상태다 — **경쟁 제품은 허용한다.**
  → 근거: 상세기획 §2-B 입력 3원칙 #3 "직전 입력을 기억한다 — 위치만 새로 찍으면 됨"은
     찍는 순간 직전 값이 채워진 결함이 생긴다는 뜻이다. A안과 정합한다.
- **B. 불허 — 필수 항목을 채워야 저장**
  → 찍으면 임시 마커만 뜨고, 부재·결함유형을 고른 뒤에 확정된다.
  → 현장에서 손이 바쁠 때(§2.5 G7 "사진 먼저 찍는 경우") 흐름이 끊긴다.
- **C. 허용하되 출력에서 자동 제외** (A + 안전장치)
  → 미완성은 저장되지만 손상결함표·리스트 출력에서 빠지고, 출력 모달에 `미완성 N건 제외됨` 표시.

**추천:** **A안**, 여유가 되면 **C안**.
경쟁 제품이 A로 동작하고, 현장 입력 속도가 이 제품의 핵심 가치이기 때문이다.

**차단 여부:** **차단** — 단 **T11(점 마커 생성) 한정.**
T1~T10(코어 기하·뷰포트·렌더·히트테스트·드래그·Undo·스냅 2종·병합)은 답 없이 착수해도
구조가 굳지 않는다. **T11만 세워두고 나머지를 진행하면 된다.**

## Q2 · plan-reviewer · 2026-08-22 · Phase 3

**막힌 지점:**
상세기획 §3-3은 "하나의 Defect에 Mark N개(긴 균열 = 표시 여러 개, 번호 1개)",
"Defect당 Label 1개"라고 한다. 그러면 **마크가 3개일 때 리더선은 몇 개이고 어디에 붙는가?**

**왜 임의로 정하면 안 되는가:**
도면에 그려지는 그림 자체가 달라지고, **리더선 각도 스냅이 무엇을 기준으로 각도를 재는지**가
여기서 정해진다. 젠트릭스 스크린샷 14장에는 마크 N개 사례가 잡히지 않아 근거가 없다.

**선택지:**
- **A. 리더선 1개 — 대표 마크에 붙는다** (`Label.anchorMarkId` 에 마크 id 저장)
  → 선이 깔끔하다. 대표 마크는 첫 마크가 기본이고 사용자가 바꿀 수 있다.
- **B. 리더선 N개 — 모든 마크에 부챗살처럼 붙는다**
  → "이 번호가 이 세 군데를 가리킨다"가 명확하다.
  → **각도 스냅이 어느 선 기준인지 모호해진다.** 이번 범위의 핵심 기능과 충돌한다.
- **C. 리더선 1개 — 마크 집합의 중심(centroid)에 붙는다** (`anchorMarkId = null`)
  → 필드 없이 자동. 다만 마크가 흩어져 있으면 선 끝이 **아무것도 없는 빈 공간**을 가리킨다.

**추천:** **A안.** 각도 스냅이 단일 앵커를 요구하고, B의 부챗살은 도면이 지저분해진다.

**차단 여부:** **비차단.**
`Label.anchorMarkId: uuid | null` 필드를 **지금 미리 정의**하면 어느 답이 와도 마이그레이션이 없다
(A → 마크 id 저장 / C → null / B → 필드 무시하고 전체 순회).
1차 구현은 **A안 + `anchorMarkId = marks[0].id`** 로 진행한다.

## Q4 · plan-reviewer · 2026-08-22 · Phase 3

**막힌 지점:** **번호 풍선의 크기가 줌에 따라 함께 커지는가, 화면상 항상 같은 크기인가?**

**왜 임의로 정하면 안 되는가:**
- **화면과 출력물이 같아 보이는지**(WYSIWYG)가 여기서 결정된다
- 줌아웃 상태에서 풍선이 너무 작아져 **누를 수 없는** 문제가 생길 수 있다
- 젠트릭스 스크린샷 근거가 **엇갈린다** — 줌아웃 화면(`_00`,`_05`)과 줌인 화면(`_02`)의
  풍선 크기 비율이 배율 차이만큼 벌어지지 않는다. 경쟁 제품이 어느 쪽인지 단정할 수 없다

**선택지:**
- **A. 도면 좌표 고정 (줌하면 함께 커짐, WYSIWYG)**
  → 출력물과 화면이 정확히 같다. 스타일 슬라이더(번호풍선 크기)의 효과가 화면에 그대로 보인다.
  → 줌아웃하면 아주 작아진다. (히트 영역만 스크린 기준 최소 12px 보장으로 보완)
- **B. 화면 고정 (항상 같은 크기)**
  → 어느 배율에서도 누르기 쉽다.
  → **화면과 출력물이 다르게 보인다.** 슬라이더로 크기를 맞춰도 화면에서 확인이 안 된다.

**추천:** **A안 + 히트 영역 최소값 보장.** 이 제품의 PC 화면은 "출력물을 정리하는 화면"이므로
화면에서 본 것이 그대로 출력되어야 한다.

**차단 여부:** **비차단.** A안으로 구현.

## Q5 · plan-reviewer · 2026-08-22 · Phase 3

**막힌 지점:** **리더선 각도 스냅에 45도 배수를 포함하는가?**

**왜 임의로 정하면 안 되는가:**
기획서 원문은 "각도가 **90도**(수직/수평) 근처에 오면 자동 직교화"만 말한다.
45도를 넣는 것은 기획서를 넘어서는 판단이고, **사용자가 원하는 사선 배치를 방해할 수 있다.**

**선택지:**
- **A. 90도 배수 4방향만** (`0/90/180/270`)
  → 기획서 문구 그대로.
  → 근거: 젠트릭스 실측 도면의 리더선 다수가 **의도적인 임의 사선**이다.
     45도를 켜면 그 사선들이 전부 45도로 끌려가 오히려 방해가 된다.
- **B. 45도 배수 8방향** (`0/45/90/…/315`)
  → 대각선 배치가 깔끔해진다. 사선 리더가 많은 도면에서는 이쪽이 나을 수 있다.

**함께 확인 부탁드리는 기본 수치** (감이 안 맞으면 숫자만 바꾸면 됩니다)
| 항목 | 제안값 |
|---|---|
| 각도 스냅 진입 | **5도** 이내 |
| 각도 스냅 이탈 | 8도 (떨림 방지) |
| 각도 스냅 최대 이동 | **12px** — 리더선이 길면 5도라도 라벨이 크게 튀므로 상한을 둠 |
| 최소 리더 길이 | 24px 미만이면 각도 스냅 끔 |
| 정렬 스냅 진입 / 이탈 | **6px / 10px** |

**추천:** **A안.** 위 수치대로 구현하고 전부 상수 한 파일(`constants.ts`)에 모은다.

**차단 여부:** **비차단.** A안 + 위 수치로 구현. `ANGLE_SNAP_45` 플래그만 켜면 B가 된다.

**막힌 지점:**
번호 풍선을 끄는 동안 **스마트 정렬 가이드**와 **리더선 각도 스냅**이 동시에 걸릴 수 있다.
같은 축을 서로 다른 값으로 당길 때 **어느 쪽이 이기는가?**

*(참고: 대부분은 싸우지 않는다. 각도 스냅이 수직이면 x만 고정하므로 y축 줄맞춤은 동시에 적용된다.
문제가 되는 건 각도 스냅이 고정한 축을 정렬 스냅도 잡으려는 경우뿐이다.)*

**왜 임의로 정하면 안 되는가:** 사용자가 손끝으로 매번 느끼는 동작이다.

**선택지:**
- **A. 각도 스냅 우선** → 리더선 직교가 지켜지고, 그 축의 줄맞춤은 포기한다.

  → 번호를 여러 개 나란히 정리하는 작업 중이라면 이쪽이 자연스럽다.

**추천:** **A안.** 어긋남이 더 크게 보이는 쪽을 지킨다.

**차단 여부:** **비차단.** `SNAP_PRIORITY = 'ANGLE_FIRST'` 상수로 구현. 한 줄로 뒤집힌다.

> 참고로 **적용되지 않은 스냅의 가이드선은 그리지 않는다.** 선은 보이는데 라벨이 안 붙어 있으면
> 사용자는 기능이 고장났다고 느낀다.

**왜 임의로 정하면 안 되는가:** 사진과 입력값까지 딸린 결함 레코드가 통째로 사라질 수 있다.

- **B. 삭제 거부** (`마지막 표기는 지울 수 없습니다`) → 결함 삭제는 리스트에서만.

**추천:** **A안.** Undo가 있으므로 위험이 낮고 조작이 가장 직관적이다.
(C안은 §2.5 G1 엑셀 임포트를 구현할 때 자연스럽게 다시 검토하게 된다)

**차단 여부:** **비차단.** A안으로 구현.

## Q8 · plan-reviewer · 2026-08-22 · Phase 3

**막힌 지점:**
PC 정리 화면에서 **전회차 표기(`PREV_PENDING` 보라 / `REPAIRED` 회색)** 를
이동·삭제할 수 있는가, 보기만 하는가?

**왜 임의로 정하면 안 되는가:**
전회차 데이터는 **이전 회차의 기록**이다. 실수로 옮기거나 지우면 대조의 기준이 사라진다.
반대로 완전히 잠그면 전회차 번호가 현회차 번호와 겹쳐 보일 때 정리할 방법이 없다.

**선택지:**
- **A. 선택만 가능 (이동·삭제 불가)** → 기준 데이터가 안전하다. 겹침은 손댈 수 없다.
- **B. 라벨(번호 풍선) 이동만 허용, 마크 이동·삭제는 불가**
  → 마크는 실제 위치라 잠기고, 번호 위치만 겹침 해소용으로 옮길 수 있다.
- **C. 현회차와 동일하게 전부 허용**

**추천:** **B안.** 실제 위치는 잠그고 표기 정리만 허용하는 것이 "PC는 정리"라는 이 화면의 목적과 맞다.

**차단 여부:** **비차단.**
1차는 가장 안전한 **A안**으로 구현하고(전회차는 정렬 가이드 후보에는 포함),
답을 받으면 B/C로 확장한다. 렌더·히트테스트 구조는 세 안 모두 동일하다.

## Q9 · builder · 2026-08-22 · Phase 3 구현

**막힌 지점:**
스펙 §2-5 는 표기를 선택하면 **"우측 결함정보 패널"** 이 뜬다고만 쓰여 있고
그 패널이 무엇을 보여주는지 정의가 없다. Phase 3 은 도면 캔버스 범위이고
결함 속성 입력(부재·결함유형 선택, 폭·길이 입력)은 Phase 2 조사입력의 영역이다.

D3(미완성 결함 허용)에서 "미완성을 채우는 경로"가 이 화면에 없어진다.

**선택지:**

**추천:** **A안 → 나중에 C안.** Phase 2 폼이 나오면 그것을 이 자리에 끼운다.

**차단 여부:** **비차단.** 1차는 A안으로 구현했다 (ASSUMPTIONS C1).

## Q10 · builder · 2026-08-22 · Phase 3 구현

## Q18 · plan-reviewer · 2026-08-23 · S4 규모 입력

**막힌 지점:**
**폭 구간 버튼이 손상결함표에 넣는 숫자가 정의돼 있지 않다.**

젠트릭스 실측 사이드바의 폭 프리셋은 **구간**이다 —
`~0.1mm미만` `0.1mm이상~0.2mm미만` `0.2mm이상~0.3mm미만` `0.3mm이상~0.5mm미만` `0.5mm이상` `직접입력`.
그런데 손상결함표에 인쇄되는 폭은 **단일 숫자 `0.2`** 이고,
면적도 그 숫자로 계산된다 (`0.2 ÷ 1000 × 2000 ÷ 1000 = 0.0004`).

즉 구간 버튼 하나를 누르면 **어떤 대표 숫자 하나가 확정돼 보고서에 찍힌다.** 그 값이 무엇인지가 없다.

**왜 임의로 정하면 안 되는가:**
이 숫자가 **보고서에 그대로 인쇄되고 면적까지 결정한다.**
`0.1~0.2` 를 0.1 로 잡느냐 0.2 로 잡느냐에 따라 같은 결함의 면적이 **2배 차이**난다.
그리고 이것은 발주처가 보는 수치라 실무 관행이 이미 정해져 있을 가능성이 높다.

**선택지:**
- **A. 구간 상한** — `~0.1미만`→0.1, `0.1~0.2`→0.2, `0.2~0.3`→0.3, `0.3~0.5`→0.5
  → 실측표의 `0.2` 와 맞는다(0.1~0.2 버튼에서 나왔다고 보면). 보수적으로 크게 잡는다
- **B. 구간 하한** — `0.1~0.2`→0.1, `0.2~0.3`→0.2
  → "이상" 값을 적는 해석. `~0.1미만` 은 0 이 되어 무의미해진다
- **C. 구간 중앙** — `0.1~0.2`→0.15
  → 소수 둘째 자리가 생겨 표가 지저분해진다

**추천:** **A안(상한).** `~0.1mm미만` 이 0.1 로 읽히는 것이 가장 자연스럽고,
실측 손상결함표의 `0.2` 와도 모순되지 않는다.
`0.5mm이상` 만 예외로 두어(상한이 없으므로) **직접입력으로 전환하고 0.5 를 초기값**으로 넣는다.

**차단 여부:** **비차단.** A안으로 확정하고 매핑을 `items/presets.ts` **상수표 한 곳**에 모았다.
답이 오면 그 표의 숫자만 바꾸면 된다.

- **C. 열을 하나 더 만든다 (`가로` `세로`)**
