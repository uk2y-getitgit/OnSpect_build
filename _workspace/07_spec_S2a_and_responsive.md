# R. 반응형 정리

## R-0. 원칙 — 화면 종류마다 다르게 대한다

| 화면 | 원칙 | 이유 |
|---|---|---|
| **캔버스** | 가로·세로를 **꽉 채운다** | 도면은 크게 볼수록 좋다 |
| **목록 · 폼 · 설정** | **max-width 컨테이너**로 읽기 편한 폭 유지 | 넓을수록 좋아지지 않는다 |

지금은 둘 다 "꽉 채우기"로 처리돼 있어 목록·설정 화면이 무너진다.

## R-1. 확인된 문제 (1920×1080 실측)

용역 셋업 화면 `ProjectSetup`:
- `지하1층` 은 왼쪽 끝, `도면 없음 / 도면 올리기` 는 오른쪽 끝 —
  **사이 약 1200px 가 비어 있다.** 눈이 좌우로 왕복해야 한다
- 층 행 전체가 같은 문제. 도면 썸네일·이름·해상도가 전부 우측 끝에 몰려 있다
- 좌측 `동` 패널과 우측 `층·도면` 패널이 **세로로 화면 끝까지** 늘어난다.
  내용은 상단 400px 뿐인데 빈 패널이 1000px 이어진다

용역 목록 `ProjectList`:
- 행이 화면 폭 전체로 늘어나 제목과 메타(`41분 전 · 도면 5장`)가 멀리 떨어진다

## R-2. 처방

1. **콘텐츠 컨테이너 도입** — 목록·폼·설정 화면 본문에 `max-width` + 가운데 정렬
   - 권장: `max-width: clamp(720px, 92vw, 1180px)`
   - 캔버스 화면에는 적용하지 않는다
2. **행 내부 레이아웃을 `1fr` 로 밀어내지 마라**
   - `justify-content: space-between` 이나 `flex:1` 스페이서로 양끝에 붙이는 방식을 걷어낸다
   - 명시적 그리드 컬럼으로 바꾼다. 예: `grid-template-columns: auto minmax(160px,320px) 1fr auto`
   - 늘어나야 하는 것은 **이름 칸 하나**로 한정하고, 나머지는 내용 폭을 유지한다
3. **세로** — 패널이 콘텐츠 높이를 따르되 최소 높이를 준다. 빈 패널이 화면 끝까지 늘어나지 않게
4. **기존 브레이크포인트(1200/980/820/720)를 유지·보완**하되, 새로 추가하지 말고
   위 컨테이너·그리드로 해결되는지 먼저 본다
5. **넓은 화면(≥1600px)에서 캔버스는 그대로 꽉 채운다.** 도면이 커야 정밀 작업이 된다

## R-3. 확인 방법 (코드로)

- 목록·폼·설정 화면 컴포넌트에서 `space-between` / 스페이서 `flex:1` 잔존 여부 grep
- 캔버스 라우트에 컨테이너 max-width가 **적용되지 않았는지** 확인

# S2a. 마커 도구 3종 + 메모

점(POINT)은 Phase 3에서 완료. 나머지를 채운다.

## S2a-1. 데이터 구조

`Mark.type` 은 이미 `POINT | ARROW | AREA_RECT | AREA_ELLIPSE` 로 정의돼 있다.
`geometry` 를 타입별로 확정한다. **전부 0~1 정규화** (불변식 #1).

| type | geometry |
|---|---|
| `POINT` | `{ x, y }` — 기존 |
| `ARROW` | `{ from: {x,y}, to: {x,y} }` — 꼬리→머리 |
| `AREA_RECT` | `{ x, y, w, h }` — 좌상단 + 크기 |
| `AREA_ELLIPSE` | `{ x, y, w, h }` — 외접 사각형 기준 |

**자유그리기**는 마크가 아니라 **결함에 종속된 스케치**다 (상세기획 §3-3 `sketch: Path[]`).
```
Path = { points: [{x,y}, ...], width: number }
```
- 결함번호와 연동된다. 출력 시 ON/OFF (Phase 4)
- 마크와 달리 번호 라벨·리더선이 붙지 않는다

**메모**는 결함과 무관한 **독립 레이어**다 (상세기획 §2 정보구조).
```
Memo = { id, projectId, floorId, pos: {x,y}, text, style?, RecordBase }
```
- IndexedDB `memos` 스토어는 S1에서 **이미 빈 채로 생성**돼 있다. 그대로 쓴다
- 결함 리스트에 나타나지 않는다. 출력 ON/OFF 별도 (Phase 4)

## S2a-2. 생성 조작

| 도구 | 조작 |
|---|---|
| 점 | 클릭 (기존) |
| 방향 | **드래그** — 누른 지점이 꼬리, 뗀 지점이 머리 |
| 영역 | **드래그** — 대각으로 사각형/타원. Shift 시 정사각/정원 |
| 그리기 | **드래그로 자유 곡선.** 뗄 때 한 Path 확정 |
| 메모 | 클릭 → 텍스트 입력 |

- 방향·영역은 **드래그 거리가 최소 임계값(스크린 8px) 미만이면 생성 취소.** 실수 클릭 방지
- 생성 직후 그 대상이 선택 상태가 된다 (점과 동일)
- **D3 결정 유지**: 마크 생성 즉시 Defect 저장. 미완성 허용

## S2a-3. 히트 테스트 우선순위

작은 것·앞에 있는 것이 이긴다. 기존 `라벨 > 마크 > 리더선` 을 확장한다.

```
1. 번호 라벨
2. 영역 리사이즈 핸들 (선택된 것만)
3. 점 마크
4. 화살표 (머리/꼬리 핸들 → 몸통)
5. 영역 테두리
6. 자유그리기 선
7. 메모
8. 영역 내부 (채움일 때만)
```

영역 내부를 마지막에 두는 이유: 큰 영역이 그 위의 작은 표기를 전부 삼키면 안 된다.

## S2a-4. 편집

- **영역**: 8방향 리사이즈 핸들 + 전체 이동
- **화살표**: 머리·꼬리 각각 이동 + 전체 이동
- **자유그리기**: 전체 이동만. 점 단위 편집은 하지 않는다 (범위 밖)
- **메모**: 이동 + 텍스트 수정 + 삭제
- 전부 **Undo/Redo 대상**. 기존 커맨드 패턴에 편입한다
- 삭제는 되돌리기 가능한 토스트 (ui-quality §4)

## S2a-5. 스타일

스크린샷 실측 기준. 영역 선택 시 컨텍스트 툴바가 달라진다.

| 대상 | 툴바 |
|---|---|
| 점 | `[점 ▾] 색상 · 복제 · 추가 · 삭제` (기존) |
| 방향 | `[방향 ▾] 색상 · 복제 · 추가 · 삭제` |
| 영역 | `[영역 ▾] 색상 · 실선 · 채움 · 복제 · 추가 · 삭제` |

영역 스타일 옵션 (상세기획 §3-5):
- 모양: **구름(revision cloud) / 점선 / 직선**
- 채우기: **투명 / 채움(45° 해치)**

**스타일 상속 규칙 필수** — 개별 변경 시 전역에서 분리되고 `[초기화]` 로만 복귀.
그리고 **위치·크기는 `style` 이 아니라 `geometry` 다.** 섞으면 정리한 결함이 상속에서 이탈한다.

## S2a-6. 색

`docs/OnSpect_디자인시스템.md` §3 예약 준수.
마크 색은 **결함 상태**(현회차 빨강 / 전회차 보라 / 보수완료 회색)가 정하고,
사용자 커스텀이 그 위에 덮어쓴다.

**메모는 결함이 아니다.** 상태색을 쓰면 안 된다.
→ 중립 색(`--text-muted` 계열 또는 노란 포스트잇 계열)으로 결함과 확실히 구분한다.
가이드 시안(`--guide`)과도 겹치지 않게 한다.

## S2a-7. 범위 밖

- 출력 시 자유그리기·메모 ON/OFF 체크박스 → Phase 4
- 결함정보 입력 패널 연결 → S2b
- 마크 그룹 편집(여러 마크를 한 번호로 묶기) → 이미 데이터 구조는 지원. UI는 범위 밖
