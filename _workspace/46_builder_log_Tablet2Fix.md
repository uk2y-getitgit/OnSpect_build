### B-1 을 어떻게 고쳤나

`TouchEvent.touches` 는 **화면 전체**의 접점 목록이다 — 그 이벤트를 받은 요소의 접점이 아니다.
`.canvas-host { position:absolute; inset:0 }` 이라 도구 팔레트·Inspector·Sidebar 는 **시각적으로만**
도면 위에 겹쳐 있고 DOM 상으로는 host 밖 형제다. 그래서 팔레트에 엄지를 얹은 채 도면에 그리면
접점이 2개로 집계 → `GESTURE_PINCH_START` → `cancelDrag` 로 방금 시작한 획이 롤백됐다.

`targetTouches` 는 실제 target 이 자식 `.canvas-layer` 캔버스라 쓸 수 없어(findings 지적대로)
포함 관계로 직접 거른다.

```ts
export function touchesIn(el: HTMLElement, list: TouchList): Touch[]
```

`Touch.target` 은 **touchstart 시점 요소로 고정**되므로, 캔버스에서 시작한 손가락을 팔레트 위로
끌고 나가도 계속 통과한다(추적이 끊기지 않는다).

**세 곳을 같이 고친 이유 —** findings 가 경고한 그대로다. `onTouchEnd` 의 `>= 2` 를 날 `e.touches`
로 남겨두면, 캔버스 손가락을 다 뗐는데 팔레트 위 엄지가 남아 `>= 2` 로 읽혀 **핀치가 영영 안 끝나고
포인터 입력이 통째로 막히는** 새 버그가 된다. 아래 회귀 하네스의 4번째 케이스가 이걸 고정했다.

**`pinchSample` 시그니처를 배열로 바꾼 것이 핵심 방어다.** `TouchList` 를 계속 받게 두면 앞으로
누군가 날 `e.touches` 를 그대로 넘겨도 컴파일이 통과한다. 배열로 바꿔 두면 필터를 건너뛴 호출이
**타입 에러로 잡힌다.**

## 알려진 한계

1. **`MemoEditor` 위 두 손가락은 여전히 핀치로 잡힌다.** `.canvas-host` 안쪽이라 포함 관계 필터로는
   안 걸러진다. findings 도 같은 판단(빈도 낮음).
2. **C-3 미수정.** 화면 동작 변경이라 사용자 결정 대기.
3. **브라우저별 `touchstart` preventDefault ↔ `pointercancel` 발행 차이는 여전히 미검증** (findings
   "확인하지 못한 것 #1" 그대로). 이번 수정은 그 지점을 건드리지 않았다.
4. **DOM 배선의 상설 테스트가 없다.** 이번엔 일회용 하네스로만 확인했다.
