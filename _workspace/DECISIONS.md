# DECISIONS

사용자가 답한 결정 사항. 에이전트는 작업 전 반드시 읽는다.

## D1 · 2026-08-22 · 구현 타겟
**PC 웹 먼저.** 캔버스 코어는 플랫폼 독립으로 작성하여 이후 RN이 재사용한다.

## D2 · 2026-08-22 · 1차 범위
**코어 + PC 정리 기능까지.** 도면 로드/줌/팬, 점 마커, 리더선, 번호 풍선, 이동·삭제, 스마트 정렬 가이드, 리더선 각도 스냅.


## D3 · 2026-08-22 · 미완성 결함 허용 (Q1 답변 — 차단 해제)
**A안: 허용 — 점을 찍는 즉시 Defect 저장.**

- 부재·결함유형이 비어 있는 미완성 결함이 존재할 수 있다
- 좌측 조사항목 리스트에 찍는 즉시 1건이 늘어난다
- 데이터 모델에 `DRAFT` 개념이 들어간다 (플래그 또는 필수항목 충족 여부 파생)
- **필요한 후속 장치:** 좌측 리스트 `미완성 N건` 배지, 출력 시 경고
- 출력에서 자동 제외(C안)는 채택하지 않음 — 사용자가 모르고 누락시킬 위험

근거: 젠트릭스가 동일하게 동작(스크린샷 _01, 마커 37번 존재 + 결함유형 `선택해주세요.`).
상세기획 §2-B 입력 3원칙 #3 "직전 입력을 기억한다 — 위치만 새로 찍으면 됨" 과 정합.

→ **T11(점 마커 생성) 착수 가능.**

## D4 · 2026-08-22 · 구현 순서 (S2 분할)
**S2를 둘로 쪼갠다.** 실행 순서:

`S1 → S2a → S3 → S4 → S2b → S5`

- **S2a** 마커 도구 4종(점·화살표·영역·자유그리기) + 메모 — 선택지 불필요, 독립 착수 가능
- **S3** 설정 화면 (결함정보 설정 = 항목 4단 계층)
- **S4** 결함정보 필드 (구조유형·부재·진행여부·규모·발생원인·보수보강방안)
- **S2b** 캔버스 결함정보 입력 패널 연결 — S3·S4의 선택지에 의존
- **S5** 사진 추가 (PC 폴더 선택)

이유: S2의 "결함정보 선택 및 입력"이 S3·S4가 만드는 선택지에 의존한다.
먼저 하면 임시 목록을 만들었다가 S3에서 갈아엎게 된다.

## D5 · 2026-08-22 · 임시 저장 전략
**브라우저 IndexedDB에 저장한다.** 새로고침해도 용역·도면·결함이 유지된다.

- 테스트 가능성이 이번 요구의 핵심이다 (사용자: "테스트가 쉽지 않네")
- Phase 5 오프라인 로컬 DB 설계를 앞당기는 것이므로 **버리는 작업이 아니다**
- 다만 S1에서는 동기화·병합·큐를 만들지 않는다. **로컬 영속 저장까지만**
- 도면 이미지 원본도 함께 보관해야 새로고침 후 렌더된다 (Blob 저장)
