### 어떻게 동작하는가 (요구사항 대응)

1. **토글은 터치 기기에서만 보인다** — 기존 T-5 규칙을 그대로 재사용했다.
   `.palette__slot--aim { display:none }` 을 기본으로 두고
   `@media (hover:none) and (pointer:coarse)` 안에서만 `display:block`.
   `.photos__capture`(P6 촬영 버튼)와 **같은 수법·같은 위치**다. JS 판정·UA 스니핑 없음.
   PC 에서는 팔레트에 조준 버튼이 아예 없다(DOM 에는 있고 CSS 로 숨는다 — 촬영 버튼과 동일).

2. **십자선은 화면(뷰포트) 정중앙 고정** — `.aim-cross` 는 캔버스 호스트 안에
   `left:50%/top:50%` 로 그린다. 도면이 아니라 화면에 붙어 있으므로 밀거나 핀치줌해도
   늘 같은 자리다. `pointer-events:none` 이라 팬/핀치를 한 픽셀도 방해하지 않는다.
   흰 halo(`box-shadow`)를 둘러 검은 도면선 위에서도 보인다.

3. **`[여기]` = 중앙 좌표 합성 탭** — `aimTapEvents(aimCenterOf(host))` 가
   `POINTER_DOWN` + `POINTER_UP`(같은 `screen`, `button:0`, `keys.space:false`) 두 개를 만들어
   기존 `send()` → 리듀서 경로로 그대로 흘려보낸다. **새 분기를 만들지 않았으므로**
   점·방향·영역·자유그리기 각각의 동작이 "그 자리를 손가락으로 탭한 것"과 정확히 같다.
   (점 = 결함 생성 / 방향·영역 = 드래그가 없으니 기존 탭과 똑같이 아무것도 만들지 않는다)
   합성 `pointerId` 는 `-1` — 브라우저가 내는 id(0 이상)와 겹치지 않는다.

4. **손가락이 목표를 가리지 않는다** —
   십자선은 화면 중앙, `[여기]`(104px 원형)는 **우하단 엄지 자리**(`right:24px bottom:28px`),
   안내 띠는 상단. 셋이 서로 겹치지 않고 중앙 목표를 아무것도 덮지 않는다. 목업 M-05a 배치 그대로.

5. **조준 중 도면 탭은 팬/줌 전용** —
   코어는 `button===0 && keys.space` 를 팬으로 읽는다(`interaction.ts` onPointerDown 943행).
   조준 중에는 포인터 3형제에 `space:true` 를 실어 보내 **Space+드래그와 완전히 같은 경로**를 타게 했다.
   그래서 도면을 아무리 탭·드래그해도 결함이 생기지 않고, 표기는 오직 `[여기]` 로만 생긴다.
   같은 이유로 조준 중에는 `DOUBLE_CLICK`·`CONTEXT_MENU` 도 코어로 보내지 않는다
   (밀다 잠시 멈췄을 때 삭제 메뉴가 뜨거나 메모 편집기가 열리는 것을 막는다).
   조준을 끄면 `KEY_UP ' '` 를 한 번 보내 코어에 남은 `keys.space` 를 푼다(커서가 손 모양으로 굳는 것 방지).

### 배치를 이렇게 잡은 이유 (경계면 사고 예방)

- **십자선은 캔버스 호스트 *안*** — `left:50%/top:50%` 가 곧 `aimCenterOf()` 가 재는 점이라
  "보이는 십자선"과 "실제 찍히는 자리"가 어긋날 수가 없다(구조적으로 같은 값).
- **`[여기]`·안내 띠는 호스트 *밖*(stage 형제)** — 호스트 안에 두면 버튼을 누른 엄지가
  `touchesIn()` 에 캔버스 접점으로 세어져 **핀치로 오인식**된다. 이건 이미 겪은 사고다
  (`pointerAdapter.ts` ⭐B-1 — 팔레트에 얹은 엄지 때문에 획이 롤백되던 버그).
- **둘 다 `data-floating` 을 붙이지 않았다** — 붙이면 안전영역(§2-10-a) 계산에 들어가
  조준을 켜고 끌 때마다 도면이 움찔 움직인다.

## 직접 확인해주실 것

**태블릿(터치 전용 기기) 실기기 확인 — PC 브라우저로는 확인되지 않는 항목:**

1. **토글 노출** — 태블릿에서 도면 화면을 연다 → 우측 툴 팔레트 맨 아래 구분선 밑에
   `⊕ 조준` 버튼이 보여야 정상. **PC(마우스) 브라우저에서는 이 버튼이 보이지 않아야 정상.**
   (크롬 개발자도구의 모바일 시뮬레이션은 `hover:none`/`pointer:coarse` 를 흉내 내므로 보인다 —
   실기기 확인이 필요한 이유)
2. **십자선 고정** — 조준을 켠다 → 화면 정중앙에 파란 십자선 + 가운데 작은 원.
   한 손가락으로 도면을 밀고 두 손가락으로 확대해도 **십자선은 화면 중앙에서 움직이지 않아야** 정상.
3. **팬 전용** — 조준이 켜진 상태에서 도면을 그냥 톡 친다(탭) → **아무 결함도 생기지 않아야** 정상.
   길게 눌러도 삭제 메뉴가 뜨지 않고, 두 번 톡 쳐도 메모 편집기가 열리지 않아야 정상.
4. **점 도구로 찍기** — 팔레트에서 `점` 을 켜고 → 목표를 십자선 아래로 맞춘 뒤 → `[여기]` 를 누른다
   → 십자선이 있던 **바로 그 자리**에 결함이 생기고 결함정보 폼이 열려야 정상.
   (십자선과 실제 찍힌 자리가 눈에 띄게 어긋나면 알려주세요 — 그 경우 원인은 배치가 아니라
   호스트 크기 측정이므로 알려주시면 그 부분만 봅니다)
5. **연속 표기** — 결함을 하나 찍은 뒤에도 **조준 모드가 꺼지지 않고** 유지돼야 정상
   (Q55 가 꼽은 안 A 의 장점 — 밀고 → 여기 → 밀고 → 여기 를 반복할 수 있어야 한다).
6. **끄기** — `⊕ 조준` 을 다시 누르면 십자선·안내 띠·`[여기]` 가 모두 사라지고,
   **예전처럼** 도면을 탭해서 바로 찍는 동작으로 돌아가야 정상.
7. **손가락 가림** — `[여기]` 를 누르는 엄지가 십자선(목표)을 가리지 않는지.
   왼손잡이라 버튼이 반대쪽에 있어야 한다면 알려주세요(좌/우 선택은 스펙에 없어 넣지 않았습니다).
8. **다른 도구** — 조준을 켜고 `영역`·`방향` 도구에서 `[여기]` 를 눌렀을 때의 동작.
   현재는 **탭 한 번과 같아서 아무것도 만들어지지 않습니다**(면적/방향은 드래그가 필요하므로).
   이게 예상과 다르면 알려주세요 — 조준으로 영역을 잡는 방식은 스펙에 정의돼 있지 않습니다.

## 알려진 한계

1. **조준 상태는 저장되지 않는다.** 화면을 나갔다 오면 꺼져 있다. D22/스펙에 지속 요구가 없어
   임의로 넣지 않았다(필요하면 `lastView:` 처럼 `meta` 에 붙이면 된다 — T2-5 와 같은 자리).
2. **영역·방향 도구는 조준으로 "그릴" 수 없다.** 합성은 탭(DOWN+UP) 하나뿐이라 드래그가 없다.
   D22 는 "지금 선택된 도구에 따라 기존과 똑같이 동작" 만 요구했고, 조준 드래그(두 번 찍어 사각형)는
   스펙에 없어 만들지 않았다. 필요하면 별도 결정이 필요하다.
3. **`[여기]` 는 왼/오른손 선택이 없다.** 목업(M-05a)이 우하단 하나만 그리고 있어 그대로 따랐다.
4. **손가락으로 도면을 끄는 도중에 `[여기]` 를 누르면 아무것도 찍히지 않는다.**
   코어가 "두 번째 포인터"(T3)로 보고 진행 중이던 드래그를 롤백한 뒤 합성 탭을 버리기 때문이다.
   엉뚱한 자리에 찍히는 것보다 안전한 쪽을 택했다(손을 떼고 누르면 정상 동작).
5. **십자선은 호스트의 기하학적 중앙**이다. 안전영역(팔레트가 잡아먹는 여백)의 중앙이 아니다.
   실기기에서 십자선이 화면 중앙보다 치우쳐 보이면 알려주세요.
