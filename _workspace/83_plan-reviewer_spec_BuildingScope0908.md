### 판정의 핵심 — 데이터 구조를 바꿀 필요가 없다

`Building`은 이미 1급 엔티티이고 `Floor.buildingId`로 층이 종속돼 있다.
출력의 유일한 범위 지정자인 **`ExportParams.floorIds`가 이미 층 배열**이므로,
"동별 출력"은 **층 선택의 부분집합**으로 전부 표현된다.

> **새 필드 0개 · 새 IndexedDB 스토어 0개 · `DB_VERSION` 1 유지 · `ExportRun` 스키마 무변경.**
> 불변식 #2(번호는 저장하지 않는다)·K20(한 `ExportRun`을 4종이 공유)이 그대로 지켜진다.

### 검토 중 발견한 **진짜 원인** (가장 중요)

사용자가 말한 *"출력물이 동 구분 없이 섞인다"* 의 직접 원인을 찾았다 —
`apps/web/src/routes/Export.tsx:572`

```ts
/** 처음 열 때의 층 순서 — 지하→지상 (불변식 #5 의 sortOrder 오름차순) */
function defaultFloorOrder(b: ProjectBundle): string[] {
  return [...b.floors].sort((x, y) => x.sortOrder - y.sortOrder).map((f) => f.id);
}
```

`Floor.sortOrder`는 **동 안에서의 순번**이다(A동 1층 = 1, B동 1층 = 1).
동을 무시하고 `sortOrder`만으로 정렬하면 출력 순서가

```
A동 1층 → B동 1층 → A동 2층 → B동 2층 → …
```

로 **동을 오가며 지그재그**가 된다. 출력 화면을 열면 이 순서가 그대로 기본 선택이므로,
그대로 [생성]하면 손상결함표 섹션도·사진첩 페이지도·번호도 전부 이 순서로 섞여 나간다.
바로 옆의 `exportFloors()`(층칩 표시용)는 **동 순위 → sortOrder**로 이미 올바르게 정렬하는데,
기본 출력 순서만 그 정렬을 안 쓴다 — 그래서 **화면의 칩 순서와 실제 출력 순서가 다르다.**

→ **B-1 한 줄 수정**(`exportFloors(b).map(f => f.id)`)으로 해결된다. 가장 먼저 할 일이다.

### A. 도면 크기(배율) 일괄 적용 — "이 동의 도면만"

**대상 파일:** `apps/web/src/routes/CanvasRoute.tsx`(`computeScale`) ·
`apps/web/src/routes/DrawingScaleDialog.tsx` · `apps/web/src/data/drawingScale.ts`

#### A-a. 지금 동작 (확인 완료)

`CanvasRoute.tsx:750`

```ts
const targets = all ? snap.drawings : snap.drawings.filter((d) => d.id === currentDrawing.id);
```

`snap.drawings`는 `loadBundle(projectId).drawings` — **용역 전체 도면**이다.
`all`(=`모든 도면` 체크)이면 다른 동의 도면까지 전부 같은 배율로 바뀌고,
**그 도면들의 결함·메모 좌표까지 함께 옮겨진다**(D37). 되돌리려면 동마다 다시 원래 배율로
맞춰야 하는데, 좌표 이동은 왕복해도 부동소수 오차가 남는다 → 사고 비용이 크다.

#### A-b. 바뀔 동작

1. 체크박스 라벨이 **`이 동(A동)의 모든 도면에 같은 배율 적용 (이 도면 외 N장)`** 이 된다.
   `N`은 **같은 동의 다른 도면 수**다(지금은 용역 전체 도면 수).
2. 동이 1개면 라벨은 **지금과 똑같이** `모든 도면에 같은 배율 적용 (이 도면 외 N장)` —
   문구도 동작도 무변화 (P1).
3. 같은 동에 다른 도면이 없으면(그 동에 도면 1장) 체크박스를 **아예 안 그린다**
   (지금도 `otherDrawingCount === 0`이면 안 그린다 — 같은 규칙을 동 안에서 센다).
4. 적용 후 토스트: `도면 3장의 크기를 125%로 바꿨습니다` (지금 문구 그대로, 건수만 동 기준).
5. **용역 전체 일괄 선택지는 두지 않는다**(U82 · Q84). 동이 2개면 동마다 한 번씩 한다.

#### A-c. 구현 제약 (builder가 반드시 지킬 것)

- **스냅샷(`scaleSnapshot.current.drawings`)은 지금처럼 용역 전체를 담는다.**
  좁히는 것은 `targets` 계산뿐이다. 스냅샷을 좁히면 `paintScale`의 되돌리기
  (`scaleTouched`에 남은 다른 도면을 스냅샷으로 복원)가 깨져,
  체크를 켰다 끄면 다른 동 도면이 미리보기 상태로 남는다.
- 대상 선정은 **순수 함수로 빼서 `data/drawingScale.ts`에 둔다** — 단위 테스트 대상.
  ```ts
  export function drawingsInBuilding(
    drawings: readonly Drawing[],
    floorBuildingId: ReadonlyMap<string, string>, // floorId → buildingId
    buildingId: string,
  ): Drawing[]
  ```
  `CanvasRoute`는 이미 `floors`·`buildings`·`resolvedFloor.buildingId`를 갖고 있다.
- `imgLayout`이 없는 옛 도면을 건너뛰는 규칙(`if (!r.ok) continue` + `skipped` 토스트)은 그대로.
- **`ProjectSetup`(용역 구성 → 도면 관리)의 배율 다이얼로그는 손대지 않는다** —
  거기서는 `otherDrawingCount`를 안 넘겨서 일괄 선택지가 애초에 없다(도면 1장씩만 적용).

### B. 출력물 — 동 경계

**설계 결론:** *"동마다 파일을 따로 낸다"가 아니라 **"한 산출물 안에서 동별로 갈린다"** 로 간다.*
(U81 · Q83-A. 사용자 답이 B/C면 B-5·B-7만 다시 손보면 되고 나머지는 그대로 쓰인다.)

**근거 3가지 — 코드에서 확인한 것:**

| 근거 | 확인 위치 |
|---|---|
| ① `ExportRun` 하나를 4종이 공유한다(K20). 동마다 run을 만들면 이 불변식이 깨지고 이력이 동 수배로 늘며 `[같은 번호로 다시 받기]`를 동마다 눌러야 한다 | `export/params.ts:119` · `Export.tsx:182` |
| ② "그 동만 뽑기"는 **이미 가능하다** — 층칩에서 그 동의 층만 고르면 `params.floorIds`가 그 동으로 좁혀지고, 사진첩 머리말도 자동으로 `{용역명} - {A동}`이 된다(`names.size === 1` 분기). 새 개념이 필요 없다 | `exportModel.ts:199` |
| ③ 4종 중 조사위치도는 **원래 층당 파일 1개**라 동 개념이 파일명에만 걸린다. 손상결함표는 이미 층 섹션 기계가 있다. 사진첩만 페이지 분할이 필요하다 | `produce.ts:129` · `damageTable.ts:306` · `photoBook.ts:145` |

#### B-a. 층 선택 화면 (`routes/export/FloorChips.tsx` · `Export.tsx`)

1. **기본 층 순서를 동 그룹 정렬로 고친다** (§1의 버그).
   `defaultFloorOrder(b)` → `exportFloors(b).map((f) => f.id)`.
   동 순위(`sortByOrder(buildings)`) → 층 `sortOrder` → id 순으로, 층칩 표시 순서와 **완전히 일치**한다.
2. `[지하→지상]` `[지상→지하]` 버튼도 **동 그룹을 유지**한다 —
   동 순위를 1차 키로, `sortOrder`를 2차 키로. 지금은 `sortOrder`만 보고 정렬해 동을 섞는다.
3. 동이 2개 이상이면 칩을 **동별 그룹으로 묶어 그린다.** 각 그룹 머리에
   동 이름 + `[이 동 전체]`·`[이 동만]`·`[이 동 해제]` 버튼.
   - `[이 동 전체]` — 이 동의 층을 **현재 선택 뒤에 이어 붙인다**(누른 순서 = 출력 순서 규칙 유지)
   - `[이 동만]` — 선택을 비우고 이 동의 층만 지하→지상 순으로 넣는다 ⭐ **"동별로 뽑기"의 진입점**
   - `[이 동 해제]` — 이 동의 층만 선택에서 뺀다
4. 동이 1개면 지금과 **완전히 같은 화면**(그룹 헤더 없음, 칩 이름에 동 이름 없음). P1.
5. 칩 이름의 동 이름 접두(`multiBuilding` 분기)는 그룹 헤더가 생기면 **중복이므로 뺀다.**

#### B-b. 손상결함표 · 결함 리스트 (`packages/project-core/src/export/damageTable.ts`)

- `DamageSection`에 `buildingId: string` · `buildingName: string`을 추가한다(모델 필드, 저장 아님).
- 섹션 제목: 동이 2개 이상이면 `■ A동 1층`, 1개면 지금 그대로 `■ 1층`.
  판정 기준은 **`buildLocations`와 같은 `input.buildings.length >= 2`** — 두 곳이 갈리면
  `위치` 열엔 동이 붙는데 섹션 제목엔 안 붙는 상태가 생긴다.
- `위치` 열은 **건드리지 않는다**(U84 · Q86).
- 엑셀(`damageTableFile.ts:90`)·인쇄 뷰(`PrintDamageTable.tsx:133`)는 둘 다 `section.title`을
  그대로 출력하므로 **수정 불필요** — 제목 조립을 코어 한 곳에서 바꾸면 둘 다 따라온다.
- 섹션은 지금처럼 `floorId`가 바뀔 때 갈린다. `floorId`는 동을 건너 유일하므로 동이 바뀌면
  섹션도 반드시 갈린다 — **추가 분기 불필요.**

#### B-c. 사진첩 (`packages/project-core/src/export/photoBook.ts` + 인쇄 뷰)

지금은 머리말이 **문서 전체에 한 줄**이고, 동이 둘 이상이면 동 이름을 **버린다**

**D45가 이 가정을 명시적으로 뒤집는다.**

- `PhotoBookInput`에 `buildingNames?: Readonly<Record<string, string>>`(층 id → 동 이름) 추가.
- `PhotoBookPage`에 `buildingName: string | null` 추가.
- **배치 규칙 변경: 동이 바뀌면 새 페이지에서 시작한다.**
  (한 페이지에 두 동의 사진이 섞이면 그 페이지 머리말이 거짓말이 되므로 **강제된다** —
  선택지가 아니다.) 마지막 페이지가 6칸을 못 채우면 **지금 규칙 그대로** 빈 칸을 테두리만 그린다.
- 머리말: `buildingName`이 있으면 `{용역명} - {동이름}`, 없으면 `{용역명}`.
  → **동이 1개인 용역은 지금 출력물과 한 글자도 안 달라진다.**
- `photoBookHeaderText(src, plan)`은 페이지 단위 계산으로 대체되므로 `PrintRoute`의
  `bookHeaderText` useMemo도 함께 정리한다.
- 캡션의 `위치`에는 지금처럼 동 이름을 **넣지 않는다**(`buildings: []`를 넘기는 2026-09-04 결정 유지).
  동은 머리말이 말한다.

⚠️ **절차 주의:** 사진첩 양식은 2026-09-04에 *목업 승인 → 코드 → 실PDF 확인* 순서로 확정된
것이다(`NEXT.md` 명시 경고). 이 변경은 머리말 텍스트(사용자가 D45로 지시)와 페이지 분할

#### B-d. 조사위치도 (`apps/web/src/export/locationMap.ts` · `produce.ts`)

- **파일명 충돌을 고친다.** 지금 `produce.ts:138`이 `suffix: page.floorName`이라
  A동 1층·B동 1층이 **똑같은 파일명**으로 내려간다

  두 동에 각각 뜨면 어느 동인지 알 수 없다. 동이 2개 이상이면 `A동 1층 — …`.
- `LocationMapPage`에 `buildingName: string | null`을 얹고, `LocationMapInput.floors`를
  `{ id, name, buildingName? }`로 넓힌다. 호출부는 `produce.ts`·`PrintRoute.tsx` 두 곳뿐이다.
- `PrintLocationMap.tsx`의 `alt`도 동을 포함한다.
- **도면 렌더 자체는 손대지 않는다.** 좌표·번호 주입 경로 무변경(불변식 #2 · 함정 #2).

## 7. 직접 확인해주실 것 (구현 후, 리더가 사용자에게 전달)

동이 **2개 이상**이고 두 동에 **같은 이름의 층**(예: 둘 다 `1층`)이 있는 용역으로 확인해주세요.

- [ ] **(A-1)** 체크를 켰다가 **다시 끄고** 적용하면 그 도면 하나만 바뀌는가(다른 도면이 미리보기 상태로 안 남는가)
- [ ] **(A-1)** 동이 1개인 용역에서 체크박스 문구가 **예전 그대로**(`모든 도면에…`)인가
- [ ] **(B-1)** 출력 화면을 처음 열었을 때 층칩의 **순번 뱃지가 왼→오 순서와 일치**하는가
