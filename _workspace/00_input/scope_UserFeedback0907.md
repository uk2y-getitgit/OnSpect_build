## 2. 동기화 오류 — `invalid input syntax for type uuid: "n10-29up"`

**원문:** "동기화 오류 확인 - 올리지 못했습니다 — invalid input syntax for type uuid: "n10-29up".
동기화는 되는듯함"

**근본 원인 확정.** `apps/web/src/store.ts:523-526` `runInput()`의 `ctx.makeId`:

```ts
makeId: () => {
  seed += 1;
  return `n${seed.toString(36)}-${Math.floor(Math.random() * 1e6).toString(36)}`;
},
```

캔버스에서 결함을 찍거나(점·영역) 표기를 만들 때(`interaction.ts`의 `createDefectAt` 등,
`ctx.makeId()` 호출부 3곳) 이 함수가 결함(Defect)·마크(Mark)·라벨의 `id`를 만든다.
`n10-29up` 형태가 정확히 이 포맷과 일치한다(`n`+seed36진법+`-`+random36진법).

반면 `Building`·`Floor`·`Drawing`·`Project`는 전부 `apps/web/src/data/factory.ts`가
`newId()`(`crypto.randomUUID()`)로 만든다 — **결함류만 UUID가 아니다.**

서버 스키마(`supabase/migrations/20260902154516_init.sql:47`)는 `records.id uuid not null` —
결함을 push하는 순간 Postgres가 거부한다. "동기화는 되는듯함"은 다른 kind(BUILDING/FLOOR/
DRAWING)는 정상 push되고 DEFECT/MEMO(캔버스 생성분)만 실패하기 때문으로 보인다.

**두 겹의 문제:**
- (a) **앞으로 만들 결함도 계속 이 포맷으로 생성된다** — `makeId()`를 `newId()`(UUID)로
  바꾸면 해결. 사용자 동작 변화 없음, 비차단. **즉시 onspect-fix 진행.**
- (b) **이미 로컬 IndexedDB에 저장된, 이 포맷으로 만들어진 기존 결함들**은 (a)만 고쳐도
  여전히 옛 id를 그대로 갖고 있어 계속 push가 실패한다. 이건 되돌리기 비용이 크고
  두 가지 해법이 갈린다 — **질문 Q78.**

## 3. 동기화 중 도면 배율(125%) 어긋남

**원문:** "도면크기 125%키운 작업물이 서버동기화시 도면은 100%비율, 작업한 결함표기만
125%로 불러와짐"

**조사:** `DrawingScaleDialog`/`CanvasRoute.tsx`의 `applyScale()`은 `storage.repo.putDrawing(d)`로
Drawing을 저장하고, `dispatch(SET_DRAWING_GEOMETRY)`로 결함·메모 좌표를 저장한다 — 코드상
둘 다 로컬에 즉시 반영되는 것처럼 보여 저장 누락은 아직 못 찾았다. push/pull 양쪽에서 DRAWING과
DEFECT가 각각 독립 kind로 동기화되므로, 한쪽만 push 실패(네트워크·타이밍)하거나 pull 순서·캐시
무효화(`releaseComposite`) 쪽에 문제가 있을 가능성이 더 크다. **원인이 100% 확정되지 않았다** —
onspect-fix가 재현 시나리오를 갖고 직접 추적해야 한다. 질문 불필요(사용자 요구가 명확 — "도면과
결함 좌표는 항상 같은 배율이어야 한다"), **onspect-fix로 착수.**

## 4. 동별 분리 기능

**원문:** "전체적으로 동별분리기능 필요 (도면크기, 출력 등등)"

## 5. 같은 용역명 동기화 시 덮어쓰기

**원문:** "같은용역명 동기화시 덮어쓰기로 용량 효율 상승"

**충돌하는 기존 결정:** D38 "항상 새 프로젝트로 만든다" — `[파일로 내보내기/가져오기]`는
같은 파일을 두 번 가져와도 안 부딪히게 **의도적으로** 매번 새 id를 발급한다. 서버 동기화
쪽(D42 `[서버에서 받기]`)은 이미 `projectId` 기준으로 dedup된다(같은 프로젝트를 다시 받아도

## 6. 전차 용역 불러오기 시 결함이 안 옴 (가장 중요)

**원문:** "전차용역 불러오기 할경우 사진도 불러와야함. (가장중요)"

**조사:** "전차 회차 연결"은 `ProjectForm.tsx`에 **중첩된 체크박스 2개**로 되어 있다:
1. "이전 용역의 동·층·도면 복사" (기본 꺼짐)
2. └ "이전 용역의 결함도 함께 가져오기" (①을 켜야 보임, 기본 꺼짐)

**단, 사진은 원천적으로 범위 밖이다** — `NEXT.md` "남은 것" 절에 명시: *"전차→금차 전환에서
'사진 승계'(전회차 사진을 그대로 복사)는 이번 범위가 아니다 — 의도적으로 안 만듦(K13,
Phase 2-D 소관)"*. 사용자 원문이 정확히 "사진도 불러와야함"이라고 짚었다 — 결함 구조 복사는
되는데 **사진은 처음부터 설계상 안 가져온다.**

**분류:** 코드 결함이 아니라 **의도적으로 비워둔 범위**(K13)일 가능성이 높다. 다만
"결함까지"도 실제로 안 됐는지(체크박스 미체크 vs 진짜 버그)는 재현 없이 못 가른다.
**질문 Q81 없이 착수 불가** — 특히 "사진까지 승계"는 새 기능(꽤 큰 작업: Blob 복제 정책 필요)이라
onspect-fix 범위를 넘는다.
