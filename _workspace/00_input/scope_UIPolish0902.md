## U-2. 캔버스 동작마다 뜨는 하단 팝업(토스트) 정리

**원인:** `packages/canvas-core/src/interaction.ts` 안에서 리듀서가 `{k:'TOAST', ...}` 이펙트를
아주 자주 낸다(생성·이동·스타일변경·초기화 등). `apps/web/src/routes/CanvasRoute.tsx`가 이걸
화면 하단에 그린다(`state.toasts`, `ui/Overlays.tsx`의 `Toasts`). 이 토스트는 `ToastHost.tsx`의
전역 토스트와 **다른 시스템**이다(건드리지 마라 — P1~P4 라우트 전용).

**결정(사용자):** "꼭 필요한 알림만" 남긴다.

**분류 기준(리더 제안) — `interaction.ts`의 TOAST 발생 지점을 이 기준으로 나눠 처리하라:**

| 분류 | 예시 텍스트 | 처리 |
|---|---|---|
| **삭제+되돌리기**(항목이 화면에서 사라져 흔적이 없다) | "결함이 삭제되었습니다"·"메모가 삭제되었습니다"·"그리기가 삭제되었습니다"·"표기가 삭제되었습니다"·"빈 메모를 지웠습니다" | **유지** — 되돌리기 진입점 역할 |
| **경고/안내**(왜 동작이 안 됐는지 설명) | "도면 안쪽에서 시작해 주세요"·"끌어서 방향을 정해 주세요"·"끌어서 크기를 지정해 주세요"·"너무 작아 적용하지 않았습니다"·"전회차 표기는 삭제할 수 없습니다"·"끌어서 선을 그려 주세요"·"끌어서 메모를 써 주세요" | **유지** — 결과가 없어서 화면만 봐선 이유를 모른다 |
| **성공 확인**(캔버스에 결과가 바로 보여서 굳이 안 알려도 되는 것) | "표기가 추가되었습니다"·"그리기로 새 결함을 만들었습니다"·"메모를 추가했습니다"·"메모가 저장되었습니다"·"영역 모양을 바꿨습니다"·"번호 위치가 변경되었습니다"·"표기 위치가 변경되었습니다"·"그리기를 옮겼습니다"·"메모를 옮겼습니다"·"전체 설정으로 되돌렸습니다"·"이미 전체 설정을 따르고 있습니다"·"이미 자동 배치 상태입니다"·"번호 위치를 초기화했습니다"·"그리기를 취소했습니다" | **제거** — 캔버스에 결과가 그 자리에 바로 보인다 |

**요청:** 위 표의 "제거" 분류에 해당하는 `TOAST` 이펙트를 리듀서 반환값에서 뺀다(커맨드는 그대로 낸다 —
Undo 스택에는 계속 쌓여야 한다. **토스트 알림만 안 뜨는 것이지 되돌리기 기능 자체는 없애면 안 된다**).
`packages/canvas-core/test/*.test.ts` 에 이 토스트 텍스트를 기대하는 테스트가 있으면 같이 정리한다
(토스트가 없어졌다는 것만 확인하고, 커맨드가 여전히 나가는지는 그대로 검증해야 한다).

**분류가 애매한 게 있으면** 리더 제안 표를 기본으로 따르되, 확신이 안 서면 QUESTIONS.md에 적어라.

## U-3. 범례 정리 — 결함유형 범례 제거 + 상태범례 문구 축약

**대상:**
- `apps/web/src/routes/TitleBlockDialog.tsx` 246~259행 "결함유형" 체크박스(`lg.showTypes`) 및
  그 값을 읽어 도면에 그리는 경로(`apps/web/src/canvas/pageDecor.ts`, `packages/canvas-core/src/legend.ts`의
  `LegendRow`/`rows` 관련 부분 — 문자 기호로 결함유형을 나열하던 것. D8 §의 "결함유형 행" 전체)
- `packages/canvas-core/src/legend.ts` 의 `STATUS_LEGEND_LABEL`(76~81행 부근)

**결정(사용자):** 결함유형 범례(예: "균열" 같은 글자기호 행)는 완전히 삭제한다. 상태범례(색 있는 3줄)만
남기고 문구를 짧게 바꾼다.

**리더가 정한 색↔문구 매핑(사용자 확인 필요, 최종 보고에 다시 확인받을 것):**

| 상태 (내부값) | 색 | 기존 문구 | 새 문구 |
|---|---|---|---|
| `CURRENT` | 빨강 | 신규(현회차) | **신규** |
| `PREV_PENDING` | 보라 | 미보수(전회차) | **결함** |
| `REPAIRED` | 회색 | 보수완료 | **보수완료**(안 바뀜) |

**요청:**
1. `legend.ts`의 `STATUS_LEGEND_LABEL`을 위 표대로 바꾼다
2. **결함유형 범례 기능 전체를 뺀다** — `showTypes` 체크박스·`rows`(결함유형 행) 생성 경로·
   관련 렌더(`legend.ts`의 `LegendRow`/`rows` 그리는 부분). **상태범례(`statusRows`) 경로는 그대로
   둔다.** `ProjectLegend`/`LegendConfig` 타입에서 `showTypes`/`rows` 필드 자체를 지울지, 아니면
   필드는 남기고 항상 무시할지는 마이그레이션 비용을 보고 builder가 정한다(단, `DB_VERSION`은
   반드시 1을 유지 — optional 필드 정리는 읽기 시점에서 무시하는 쪽이 안전하다)
3. `apps/web/src/routes/settings/DefectTypeColumn.tsx`(결함유형 설정의 기호 입력칸)는 **손대지 마라**
   — 그 화면은 항목 설정이지 범례가 아니다. 다만 그 값을 쓰는 곳이 legend 경로뿐이었다면 죽은 코드가
   되는데, 지우지 말고 남겨둬라(나중에 다시 쓸 수도 있다)
4. 위 문구 매핑이 다른 화면(Sidebar 카운트·Inspector 상태 선택기·출력 옵션 패널 등)에도 나오지만,
   **이번 요청은 "범례" 한정이다.** 다른 화면의 문구는 건드리지 마라 — 사용자가 범례만 콕 집어 요청했다

## U-4. PC/태블릿 구분 배포 (리더가 직접 처리, builder 배정 없음)

리더가 별도로 처리한다 — 인프라 설정(vercel.json 리다이렉트) + 작은 UI 모드 오버라이드 훅.
이 파일에는 기록만 남긴다: 태블릿 전용 UI 판정은 지금 CSS 미디어쿼리(`hover:none and pointer:coarse`)
하나로만 되어 있어, 실제 태블릿이 없어도 URL로 강제 전환할 수 있는 오버라이드가 필요했다.
`?ui=tablet` / `?ui=pc` 쿼리 → `localStorage` 에 저장 → 그 값이 있으면 미디어쿼리 대신 그 값을 쓴다.
`/pc`·`/tablet` 별도 주소는 `vercel.json` rewrite 로 그 쿼리를 자동으로 붙여준다.
