## 1️⃣ S5 — 사진 추가 (PC 폴더 선택)

기준: `OnSpect_상세기획.md` §2-C (라인 501~541). 발췌:

- 모델: `Photo { id, defectId, isPrimary, sortOrder, localUri/remoteUrl, 촬영시각, 촬영기기, edits:{crop,rotate}, annotations }`
- 규칙: 결함 1건 : 사진 N장, 대표 1장(`isPrimary`) 정확히 1장 — **불변식 #8**
- 손상결함표·사진첩의 사진번호는 **대표사진 기준**
- 첫 장은 자동 대표, 이후 썸네일 롱프레스(PC는 우클릭 또는 메뉴)로 `[대표로 지정]`
- 플로우: `[+ 사진 추가] → 촬영/갤러리 → 확인 팝업(미리보기) → [보정]자르기·회전 [주석]그리기·화살표 [대표지정][교체][삭제] → 등록`
- **PC 웹이므로 "촬영"은 없다. 폴더/파일 선택(`<input type=file multiple>`)만 구현한다.**
- `photos` IndexedDB 스토어는 S1에서 이미 빈 채로 만들어져 있다. 그대로 쓴다 (DB 마이그레이션 금지 — 버전 1 유지)
- 결함 우측 패널(Inspector/DefectInfoForm 영역)에 사진 섹션을 붙인다. S2b가 만든 패널 구조를 재사용한다.
- 샘플 사진 8장: `샘플사진\` (로컬에만 있음, git에 없음) — 테스트/시딩용으로 참고 가능하면 활용, 없어도 무방(폴더 선택 UI 자체가 실물 파일 없이도 동작해야 함)

## 2️⃣ Phase 4 — 산출물 출력 4종

기준: `OnSpect_상세기획.md` §4(번호체계, 라인 265~308) · §5(손상결함표, 라인 310~328) · §6(산출물목록, 라인 330~340) · §2-C.

### 공통 — 번호 부여 (§4, 저장하지 않는다 — 함정 #1)

```
입력: 선택된 층 목록(클릭 순서대로), 번호모드(층별리셋/전체연속), 조사구분 필터, 보수완료 포함여부
1. 필터 통과한 결함을 층 순서 → 층 내 seq 순으로 나열
2. 번호모드에 따라 NO 부여 (층별리셋: 층 바뀔 때마다 1로 / 전체연속: 끝까지 증가)
3. 사진번호는 별도 카운터, 사진이 있는 결함(대표사진 존재)에만 증가
4. 매핑 결과를 ExportRun에 스냅샷 저장 → 재다운로드 시 동일 번호 재현
```
- 층 선택 UX: 라디오 2개가 아니라 **층 칩을 고른 순서 = 번호 순서** (젠트릭스 방식). 칩에 부여될 번호범위를 실시간 표시.
- 출력 ON/OFF 체크박스(자유그리기·메모·도곽)도 이번에 붙인다.

### 2-a. 손상결함표 (엑셀)

- **실물 서식(HWP/엑셀)을 아직 받지 못했다.** §5의 실측 열 구성으로 **표준 구조를 우선 구현**하고,
  서식이 오면 열 매핑만 조정할 수 있도록 열 정의를 한 곳(상수/설정)에 모은다.
- 열: `NO | 위치 | 부재명 | 구조체 유형 | 결함의 유형 및 형상 | 폭(mm) | 길이(mm) | 면적(㎡) | 개소(EA) | 진행상황 | 누수여부 | 발생원인 추정 | 사진번호`
- 구조: 머리말(`{현장명}` / `제2장 현장조사` / `<계속>`), 층마다 `■ {층이름}` 섹션 헤더, `손상규모`는 폭·길이·면적·개소 4열 병합헤더, 발생원인은 숫자 코드(범례 별도, `CauseMaster.code` — F6 기존 결정 재사용).
- 위치 열 = `층이름 + locationNote(위치보조)` 조합으로 채운다(§2-2 F7 필드 재사용).
- 미완성 결함(D3) 처리: 출력 대상에서 자동 제외하지 않는다(D3 결정) — 경고 표시로 포함 여부를 사용자가 판단하게 한다.
- 엑셀 생성 라이브러리는 번들 크기·라이선스를 고려해 가벼운 것으로 builder가 선정하고 ASSUMPTIONS에 근거를 남긴다.

### 2-b. 결함 리스트 (A4 세로, PDF/엑셀)

- 손상결함표와 컬럼셋은 유사하되 세로 리스트 레이아웃. 페이지네이션(A4 기준) 필요.

### 2-c. 사진첩 (6장/페이지, PDF)

- **S5(사진 업로드) 완료 후 착수** — 종속관계 있음. builder는 S5를 먼저 끝내고 이 항목으로 넘어간다.
- 대표사진 기준(§2-C 규칙)으로 사진번호를 매기고, 페이지당 6장 그리드.

### 2-d. 조사위치도 (도면 + 번호, PDF/JPG)

- 재료는 이미 준비됨: 도곽·범례가 F5에서 완성돼 있다(`Drawing` 레코드의 도곽/범례 필드, H2/H3 참조).
- 도면 위에 출력용 결함번호(NO, 저장 안 함 — 위 공통 번호부여 함수로 계산)를 얹어 래스터/PDF로 뽑는다.
- 캔버스 코어가 만드는 `DrawOp[]`(B16, 플랫폼 독립 그리기 명령)를 출력 렌더 어댑터로 재사용할 것 — 화면과 출력이 어긋나지 않게.

## 이미 확정된 관련 결정 (뒤집지 않는다)

- **F6** — 발생원인 코드(`CauseMaster.code`)는 마스터 고정값. 손상결함표는 그대로 인쇄.
- **B1** — 캔버스가 그리는 표시 번호는 `Defect.seq`(입력순번)이고, 출력 NO는 별도로 렌더 시 주입.
- **D3** — 미완성 결함 허용, 출력 시 경고(자동 제외 아님).
- **H2/H3** — 도곽·범례는 `Drawing` 레코드 저장, 범례 기호는 결함유형 이름 약어.
- **F4** — AREA(가로×세로) 입력 시 손상결함표 폭·길이 열은 `0·0`.
- 면적 절사: `(폭mm/1000)×(길이mm/1000)`, 소수 4자리 절사, 개소는 곱하지 않음 (F17 계산법 재사용).

## plan-reviewer에게

1. S5(사진)와 Phase4(4개 출력물)를 작업 단위로 분해한다. **S5 → 사진첩은 순서 의존**, 나머지 3개(손상결함표·결함리스트·조사위치도)는 병렬 가능.
2. 공통 번호부여 로직(`export/numbering.ts` 류)을 먼저 설계해 4개 출력물이 공유하게 한다 — 각자 구현하면 번호가 어긋날 위험.
3. 스펙에 없거나 모호한 지점(예: 엑셀 라이브러리 선택, PDF 생성 방식, `ExportRun` 스토어 필드 형태 — S1 ASSUMPTIONS에서 "Phase 4 소관, 형태 미확정이라 인덱스 안 잡음"이라고 보류해 둔 부분)을 이번에 확정한다.
4. `ExportRun`은 새 IndexedDB 스토어가 필요할 수 있는데 **DB 마이그레이션 금지(버전 1 유지)** 규칙과 충돌 여부 확인 — S1에서 빈 스토어를 미리 만들어 뒀는지 확인하고, 없다면 어떻게 우회할지(예: 별도 스토어 없이 파일 자체에 메타를 내장하거나, 기존 스토어 중 하나를 재사용) 판단해 차단 여부 결정.
5. 사진 보정(자르기·회전)·주석(그리기·화살표) UI 구현 난이도가 높으면 1차 범위를 좁힐 수 있는지 판단하고, 좁힌다면 어디까지가 "만들어졌다"고 볼 수 있는지 명시.
