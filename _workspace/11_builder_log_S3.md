## 직접 확인해주실 것

### A. 진입과 스냅샷

1. **P3 용역 구성 → 상단 `[설정]`** 을 누른다 → 3컬럼 화면이 열리고, 헤더에 **파란 배지로 용역 표시명**이,
   그 아래에 `이 설정은 {용역명} 에만 적용됩니다` 안내가 보이는가 (D6 의 핵심 — 어느 용역인지 늘 보여야 한다)
2. **캔버스에서 `[설정]`** → `[닫기]` → **들어왔던 그 층의 캔버스**로 돌아오는가.
   P3 에서 들어갔을 때는 P3 으로 돌아오는가
3. 설정 화면에서 **F5 새로고침** → 같은 화면이 그대로 열리는가 (해시 라우팅)
4. **S1·S2a 로 이미 만들어 둔 옛 용역**을 열어도 설정이 정상으로 뜨는가 (지연 스냅샷)
5. 용역을 **두 개** 만들어 A 에서 부재 이름을 고친 뒤, B 의 설정에 그 변경이 **없는지** 확인

### B. 목록 편집

6. 컬럼1 에서 부재를 클릭 → 컬럼2 헤더가 `{부재}의 결함유형` 으로 바뀌고 목록이 갈리는가.
   선택된 행에 **파란 좌측 바 + 옅은 파란 배경 + ▸** 가 보이고, **마우스만 올린 행(회색)과 구분**되는가
7. 컬럼2 에서 `망상균열` 의 라디오를 `폭×길이` 로 바꾼 뒤 → **다른 부재**의 `망상균열` 은 그대로 `면적` 인가
8. `[새 부재]` 에 **이미 목록에 있는 이름**을 넣고 `[추가]` → 입력줄이 **흔들리고** `이미 이 목록에 있습니다` 가 뜨는가
9. 부재 하나를 `⋯ → RC 목록에서 빼기` → 그 부재를 다시 `[추가]` → 토스트에
   `'{이름}' 은 이미 등록된 항목입니다. 이 구조유형에 연결했습니다.` 가 뜨고 **목록 맨 아래**에 붙는가
10. `⠿` 핸들을 끌어 순서를 바꾼다 → 놓는 순간 반영되고, **새로고침 후에도 그 순서인가**
11. `⋯ → 위로 / 아래로` 로도 순서가 바뀌는가 (키보드 사용자 경로)
12. 행의 `⋯ → 마스터에서 완전히 삭제` → 확인창에 **`구조유형 3개의 부재 목록에서 사라집니다`** 같은
    실제 건수와, 결함이 있다면 `이미 입력된 결함 N건은 그대로 유지됩니다` 가 나오는가
13. 12 를 실행한 뒤 토스트의 `[되돌리기]` → 지운 항목과 링크가 **전부** 돌아오는가
14. 컬럼3 에서 `[기본값으로]` 를 누르면 `기본값` 배지가 그 줄로 옮겨 가는가.
    기본값인 항목을 `🗑` 로 빼면 **남은 첫 줄**이 기본값이 되는가
15. 코드 배지 `①` 을 눌러 **이미 쓰는 번호**로 바꾸면 `코드번호 N 는 이미 쓰고 있습니다` 로 거부되는가

### C. 기타 탭

16. `기타 → 구조유형 기본값` 을 `SRC` 로 → 새로고침 후에도 유지되는가
17. `[기본 항목 세트 다시 불러오기]` — 아무것도 안 지운 상태에서 누르면
    `기본 항목이 이미 전부 있습니다` 가 뜨는가 (**아무것도 중복 생성되지 않아야 한다**)
18. 부재 하나를 완전히 삭제한 뒤 17 을 다시 누르면 `부재 1개를 추가했습니다.` 가 뜨고,
    되살아난 부재에 **결함유형 13종이 붙어** 있는가
19. `[이 설정을 기본값으로 저장]` → 확인 → 그 뒤 **새 용역**을 만들어 설정을 열면 바뀐 이름이 보이고,
    **기존 용역**의 설정은 그대로인가

### D. UI 품질 (감각으로 판단할 것)

20. 창 폭 **1920px · 1280px · 1100px** 에서 3컬럼이 각각 어떻게 접히는가. 읽히는가
21. `계단참 슬래브` · `마감박리/박락` · `재료분리, 시공불량` 이 **어절 중간에서 깨지지 않는가**
22. `Tab` 키만으로 탭 → 추가 입력 → 목록 → `⋯` 메뉴까지 갈 수 있는가.
    구조유형 탭에서 **←/→ 키로 RC·SS·SRC 를 오갈 수 있는가**
23. 항목을 빠르게 여러 번 고쳐도 화면이 즉시 반응하는가 (저장은 250ms 뒤에 뒤따라간다)
24. 씨앗 부재 17종·결함유형 13종의 **이름·순서·규모모드·구조체 구분이 실무와 맞는가** (Q20 — 아직 열린 질문)

| 3 | 저장은 250ms 디바운스다. 마지막 조작 직후 **브라우저를 강제 종료**하면 그 한 번이 유실될 수 있다 (`beforeunload` 에서 flush 를 걸어 두었으나 IndexedDB 쓰기 완료는 보장되지 않는다) |
| 4 | 결함유형·원인·보수방안의 **마스터 삭제는 구조유형과 무관하게 전역**이다. UI 문구로만 알린다 |
| 5 | `입력 미리보기` 가 비활성이라, 설정 변경이 실제 입력 화면에 어떻게 보이는지는 **S4 이후에야** 확인할 수 있다 |
| 6 | 씨앗의 도메인 정확성(Q20)은 여전히 미확인. 다만 전부 화면에서 수정 가능하고 기존 결함에 영향이 없다 |
