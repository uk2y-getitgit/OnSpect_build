## C-3 — 면적 직접입력 삭제 (D31)

### 달라지는 것
규모에서 `면적` 모드를 고르면 이제 **가로 · 세로 · 면적(읽기전용) · 개소** 가 바로 뜬다.

- 면적 직접입력 칸이 없어졌다. `가로 × 세로로 계산 ▾` **접기 토글도 없앴다** —
  가로×세로가 이제 기본 입력이라 접을 이유가 없다
- 면적은 가로×세로에서 계산된 값만 보여준다 (절사 규칙 그대로: `(폭mm/1000)×(길이mm/1000)`, 소수 4자리 절사)

### 옛 데이터 보호가 이 항목의 핵심
`areaM2` 만 있고 `areaWMm`·`areaHMm` 가 `null` 인 예전 "AREA(직접)" 입력분이 있다.
이 값은 `outputSize`(`items/size.ts:49`)를 타고 **손상결함표에 그대로 인쇄된다.**

- 값을 **지우지 않는다.** 면적 칸에 그대로 읽기전용으로 뜬다
- 가로 · 세로를 **둘 다** 채우면 그때 계산값으로 덮어쓴다
- 한쪽만 채운 중간 상태나 다시 비운 상태에서는 **옛 값을 건드리지 않는다**
  (F15 "모드를 전환해도 반대편 값을 지우지 않는다" 와 같은 원칙)

면적 칸 아래 문구가 출처를 밝힌다 — "왜 이건 못 고치지" 가 안 생기게:

| 출처 | 문구 |
|---|---|
| `RECT` | 가로 × 세로로 자동 계산됩니다 |
| `LEGACY_DIRECT` | 예전에 직접 입력된 값입니다. 가로 · 세로를 모두 채우면 대체됩니다 |
| `EMPTY` | 가로 · 세로를 모두 입력하면 계산됩니다 |

### 판정 로직은 `project-core` 로 뺐다
`apps/web` 에는 테스트 러너가 없다. 위험한 판정은 전부 순수 함수로 내려 단위테스트로 고정했다.

`packages/project-core/src/items/size.ts` 에 추가:
- `areaSource(a): 'RECT' | 'LEGACY_DIRECT' | 'EMPTY'`
- `displayAreaM2(a)` — 화면에 보여줄 값 (RECT 면 계산이 저장값을 이긴다)
- `resolveAreaM2OnRectEdit(prev, w, h)` — 가로·세로 편집 시 저장할 값

**저장 스키마 변경 0 · `DB_VERSION` 1 유지.** 새 필드를 만들지 않았다.

## 태블릿 표시 프로파일 (T-1 · T-2 · T-4 · T-5 · T-6 · D29)

`DefectInfoForm` 에 `profile?: 'full' | 'field'` 를 추가했다. 기본값 `full`.

| 항목 | 현장(`field`) 프로파일 |
|---|---|
| T-1 조사구분 | **감춤** |
| T-2 구조유형 | 노출 (변경 없음) |
| T-3 부재 | 노출 — 5종 제한은 **B9 소관**, 이번 배치 범위 아님 |
| T-4 구조체여부 | **감춤** |
| T-5 규모 | 노출 (C-3 변경은 태블릿에도 같이 적용) |
| T-6 발생원인·보수보강방안·위치보조·메모 | **감춤** |
| Q73 진행여부·누수여부·유사결함 불러오기 | **남김** (추천 A안) |

### 값은 손대지 않는다
`profile` 은 **렌더 분기일 뿐이고 `onChange` 를 부르지 않는다.** 전회차에서 넘어온 값도,
PC 에서 채운 값도 그대로 살아 있고 PC 에서 열면 다시 보인다.
손상결함표의 발생원인 · 보수방안 열은 PC 에서 채우는 것으로 남는다(D29).

### T-1 에 부수 효과가 필요 없는 이유
`EMPTY_DEFECT_ATTRS.surveyKind` 가 이미 `'EXTERIOR'` 다
(`packages/canvas-core/src/defectAttrs.ts:15`). 새 결함은 감추기만 해도 외관조사로 저장된다.
PC 에서 상세조사로 지정해 둔 결함의 값은 건드리지 않는다.
**폼에서 `useEffect` 로 값을 강제하지 않았다** — 렌더 중 `onChange` 를 부르면 저장 루프가 생긴다.

### RN 재사용 경계를 지켰다
`ui/defectForm/*` 은 store · repo · 캔버스를 import 하지 않는다(절대규칙).
`useUiMode` 같은 DOM 훅도 폼 안에서 부르지 않았다 — **호출자인 `Inspector` 가 판정해서
`profile` 로 내려준다.** `Inspector` 는 앱 쪽 컴포넌트라 이 경계에 걸리지 않는다.

`Inspector` 의 `useUiMode()` 는 `if (!defect)` 조기 반환보다 **먼저** 부른다(훅 규칙).

## 범위 밖에서 눈에 띈 것 (고치지 않았다)

- `SizeBlock` 의 `WL` 모드 면적 칸은 `effectiveAreaM2` 를, `AREA` 모드는 새 `displayAreaM2` 를 쓴다.
  둘 다 맞지만 진입점이 둘이다. 나중에 하나로 합칠 여지가 있다.
- `outputSize` 는 `sizeMode === 'AREA'` 일 때 폭·길이를 0 으로 낸다(실측 근거 있음, Q19·F4).
  이제 가로·세로를 항상 입력받으므로 **손상결함표에 그 값을 실을지** 는 별도 판단이 필요하다 —
  실무 서식 확인이 필요해 건드리지 않았다.

## 직접 확인해주실 것

1. **새 결함 · 면적 모드** → 가로 · 세로가 바로 보이고, 둘 다 채우면 면적이 계산돼 뜬다
2. **옛 결함(면적만 직접 입력했던 것)** → 면적 칸에 그 값이 그대로 뜨고 "예전에 직접 입력된 값입니다" 문구
3. **그 옛 결함에 가로 · 세로를 둘 다 입력** → 면적이 계산값으로 바뀐다
4. **가로만 입력하고 세로를 비워 둔 상태** → 옛 면적값이 사라지지 않는다
5. **손상결함표 출력** → 옛 결함의 면적 수치가 예전과 같다 (⚠️ 가장 중요)
6. **PC 화면** → 조사구분 · 구조체여부 · 발생원인 · 보수보강방안 · 위치보조 · 메모가 **전부 그대로** 보인다
7. **태블릿(`/tablet`)** → 위 6개가 안 보이고, 구조유형 · 부재 · 결함유형 · 진행여부 · 규모 · 누수여부 · 유사결함 불러오기는 보인다
8. **태블릿에서 만든 결함을 PC 에서 열기** → 감춰졌던 필드가 보이고, 조사구분이 `외관조사` 로 들어가 있다
9. **전회차에서 넘어온 결함을 태블릿에서 열었다가 PC 로** → 발생원인 · 보수방안 값이 안 지워졌다
