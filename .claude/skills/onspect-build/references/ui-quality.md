# UI 품질 기준

> 사용자 명시 요구: **"UI 하나하나 신경써서 만들어야 한다.
> 버튼 클릭하면 나오는 화면, 마우스 올렸을 때 강조 표시가 나오는지,
> 글씨가 줄바꿈이 생기는지 자연스럽게 넘어가는지 이런 것도 하나씩."**

이 문서의 항목은 **취향이 아니라 기능 요건**이다. 빠지면 결함으로 취급한다.

## 1. 인터랙션 상태 — 모든 조작 요소

버튼·탭·리스트행·칩·토글·마커·라벨 **전부**에 아래 상태를 정의한다.
하나라도 빠지면 미완성이다.

| 상태 | 언제 | 없으면 생기는 일 |
|---|---|---|
| `default` | 평상시 | — |
| `hover` | 마우스 올림 | **이게 눌리는 것인지 알 수 없다.** 가장 자주 빠지고 가장 티가 난다 |
| `active` | 누르는 중 | 눌렀는지 확신이 안 서서 두 번 누른다 |
| `focus` | 키보드 탭 이동 | 키보드로 조작 불가. 접근성 위반 |
| `selected` | 현재 선택됨 | 지금 뭘 고른 상태인지 모른다 |
| `disabled` | 쓸 수 없음 | 눌러보고 나서야 안 된다는 걸 안다 |
| `loading` | 처리 중 | 멈춘 줄 알고 다시 누른다 |

### 규칙

- **`hover` 와 `selected` 는 서로 구분돼야 한다.** 같은 색이면 마우스를 올린 것과 고른 것이 구별되지 않는다
  - 권장: `hover` = 배경 톤 변화(`--surface-2`), `selected` = `--accent-weak` 배경 + 좌측 4px `--accent` 바
- **`focus` 는 `hover` 와 달라야 한다.** `outline: 2px solid var(--accent); outline-offset: 2px`
- **터치 기기에는 `hover` 가 없다.** `@media (hover: hover)` 로 감싸지 않으면
  모바일에서 탭한 뒤 hover 상태가 눌어붙는다
- `disabled` 는 흐리게만 하지 말고 **커서도 `not-allowed`** 로 바꾼다

### 캔버스 위 요소도 예외가 아니다

마커·번호 풍선·리더선은 DOM이 아니어도 상태가 필요하다.

| 요소 | hover | selected |
|---|---|---|
| 마커 | 반경 +2px, 그림자 | 선택 핸들 표시 + `--selection` 링 |
| 번호 풍선 | 테두리 굵기 +1 | 드래그 핸들, 리더선 강조 |
| 리더선 | 굵기 +1, 커서 `move` | 양 끝점 핸들 |

## 2. 텍스트 — 줄바꿈·말줄임

**경쟁 제품이 실제로 놓친 지점이다.** 젠트릭스 부재 버튼에서
`계단참 슬래 / 브`, `벽(비구조 / 체)` 로 라벨이 깨져 있다.
현장에서 버튼을 눈으로 훑어야 하는데 라벨이 깨지면 그만큼 느려진다.

### 판단 기준

| 상황 | 처리 |
|---|---|
| 버튼·칩 라벨 | **깨지면 안 된다.** 한 줄 유지가 원칙 |
| 리스트 행의 항목명 | 한 줄 + 말줄임(`…`) + `title` 툴팁 |
| 표 셀 | 열 폭에 맞춰 말줄임. 숫자 열은 절대 줄바꿈 금지 |
| 설명문·메모 | 자연스러운 줄바꿈 허용 |

### 한국어 줄바꿈

```css
.label { word-break: keep-all; overflow-wrap: break-word; }
```

`word-break: break-all` 을 쓰면 **한글 단어 한가운데가 잘린다.** 절대 쓰지 않는다.
`keep-all` 은 어절 단위로 넘겨서 `계단참 / 슬래브` 로 끊는다 — `계단참 슬래 / 브` 가 아니라.

### 버튼 그리드에서 라벨 길이가 제각각일 때

부재 목록은 `보`(1자)부터 `계단참 슬래브`(7자)까지 섞여 있다.

- 그리드 셀 폭을 고정하지 말고 `auto-fit` + `minmax` 로 흐르게 한다
- 그래도 긴 라벨이 깨지면 **버튼 안에서 글자 크기를 줄이지 말고**, 셀을 2칸 차지하게 한다
- 최후 수단으로만 말줄임 + 툴팁

### 숫자

```css
.num { font-family: var(--font-num); font-variant-numeric: tabular-nums; }
```
표에서 자릿수가 정렬되고 `0.2` 와 `0.02` 가 구분된다.

## 3. 커서 — 캔버스에서 특히 중요

캔버스 앱에서 커서는 **"지금 여기서 무엇을 할 수 있는가"를 알려주는 유일한 신호**다.

| 상황 | 커서 |
|---|---|
| 점 찍기 도구 활성 | `crosshair` |
| 빈 캔버스 (팬 가능) | `grab` |
| 팬 드래그 중 | `grabbing` |
| 마커·라벨 위 | `move` |
| 리더선 끝점 핸들 위 | `crosshair` 또는 방향 리사이즈 |
| 도구 없음 / 읽기전용 | `default` |
| 처리 중 | `wait` |

도구를 바꿨는데 커서가 그대로면 사용자는 도구가 안 바뀐 줄 안다.

## 4. 피드백 — 눌렀는데 아무 일도 없으면 안 된다

모든 조작에는 **즉시 보이는 반응**이 있어야 한다. 서버 응답을 기다리지 않는다.

| 조작 | 즉시 반응 |
|---|---|
| 마커 생성 | 그 자리에 바로 그려짐 + 번호 부여 + 선택 상태 |
| 결함 정보 수정 | 필드 반영 + 저장 토스트 |
| 삭제 | 즉시 사라짐 + **되돌리기 가능한 토스트** |
| 도면 전환 | 로딩 표시 → 렌더 |

토스트 문구는 짧고 사실만. 젠트릭스 사례: `조사 내용이 수정되었습니다`, `사진이 추가되었습니다`.

**삭제는 확인 팝업 대신 되돌리기 토스트를 권장한다.**
현장에서 확인 팝업은 조작을 느리게 만들고, 결국 습관적으로 확인을 누르게 된다.

## 5. 빈 상태 · 로딩 · 에러

리스트나 캔버스가 그냥 비어 있으면 **고장 난 것처럼 보인다.**

| 상황 | 필요한 것 |
|---|---|
| 결함 0건 | "아직 입력된 결함이 없습니다" + 다음 행동 안내 |
| 도면 없는 층 | "이 층에 등록된 도면이 없습니다" + [도면 등록] |
| 도면 로딩 중 | 스켈레톤 또는 진행률. 흰 화면 금지 |
| 도면 로드 실패 | 원인 + [다시 시도] |
| 검색 결과 없음 | 검색어를 다시 보여주고 초기화 버튼 |

---

## 6. 전이(transition)

도구는 빨라야 한다. **과한 애니메이션은 결함이다.**

| 대상 | 시간 |
|---|---|
| hover 색 변화 | 100~120ms |
| 패널 열림/닫힘 | 160~200ms |
| 토스트 등장 | 150ms |
| 캔버스 줌/팬 | **0ms — 즉시.** 관성이나 이징을 넣으면 정밀 조작이 불가능해진다 |

```css
@media (prefers-reduced-motion: reduce){ *{ transition:none !important; animation:none !important } }
```

## 7. 자가 점검 — 코드로 확인한다

> **검증 분담 (사용자 지시 2026-08-22, 갱신):**
> *"직접 구현된 기능을 웹에서 실행하고 검증하는 과정이 너무 오래걸리고 예산을 너무 많이 사용되고 있어.
>  UI와 직접 작업을 진행하는 건 내가 하고, 오류를 다시 알려주면
>  해당 오류에 대한 확인과 수정만 다시 진행해줘."*
>
> **에이전트는 브라우저를 띄우지 않는다.** 개발 서버 실행·화면 조작·스모크 확인 전부 하지 않는다.
> **코드에서 확인할 수 있는 것만 확인하고,** 나머지는 **체크리스트로 넘긴다.**
> 사용자가 써보고 오류를 알려주면 `onspect-fix` 로 그 오류만 고친다.

### 7-1. 코드로 확인 (에이전트 책임 — 반드시)

브라우저 없이 소스에서 확인 가능하다. 하나라도 빠지면 미완성이다.

1. **조작 요소 전수 조사** — 모든 `button` / `[role=option]` / 클릭 핸들러를 grep 하고,
   각각에 `:hover` `:focus-visible` `[aria-selected]` `:disabled` 스타일이 정의됐는지 대조
2. **`hover` 와 `selected` 가 다른 값인지** CSS에서 직접 비교. 같은 색이면 결함
3. **`word-break: break-all` 이 없는지** 전역 grep. 있으면 한글이 잘린다
4. **접근 이름** — 아이콘 전용 버튼에 `aria-label` 이 있는지
5. **`@media (hover: hover)` 로 감쌌는지** — 안 그러면 터치에서 hover가 눌어붙는다
6. **`prefers-reduced-motion` 대응**이 있는지
7. **타입 검사 · 단위 테스트 · 프로덕션 빌드** 전부 통과

### 7-2. 사용자 확인 체크리스트 (산출물로 넘긴다)

빌드 로그에 `## 직접 확인해주실 것` 섹션을 만들고, **클릭해봐야 아는 것**만 적는다.
각 항목은 `무엇을 → 어떻게 → 무엇이 보여야 정상` 형식으로 쓴다.

```markdown
## 직접 확인해주실 것
1. 용역 목록에서 행에 마우스를 올린다 → 배경이 옅게 바뀌고, 선택된 행과 구분되는가
2. Tab 키로 폼을 돌아본다 → 포커스 테두리가 보이고 순서가 위에서 아래인가
3. 창 폭을 900px로 줄인다 → 라벨이 깨지거나 넘치는 곳이 있는가
4. 용역명에 아주 긴 문자열을 넣는다 → 목록에서 말줄임되는가, 깨지는가
```

**감각으로만 판단되는 것**(스냅 감도, 색 대비, 기본 배율)은 반드시 여기 넣는다.
에이전트가 수치로 정할 수 없는 영역이다.

### 7-3. 하지 말 것

- **개발 서버를 띄우거나 브라우저를 조작하기** — 예산의 가장 큰 낭비다
- 코드 확인(7-1)을 건너뛰고 전부 "사용자가 볼 것"으로 미루기
- 확인하지 않은 것을 확인했다고 적기 — 못 한 것은 `미검증` 으로 적는다
